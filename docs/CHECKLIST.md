# 수정 후 확인 순서

파일을 고친 뒤 배포하기 전에 아래 순서대로 확인합니다. 터미널에서 `buildup365/` 폴더로 들어가서 실행합니다.

## 1. 처음 한 번: 준비

```bash
cd comely15-web      # 저장소 루트
npm install          # 패키지는 루트에 한 번만 설치됩니다 (여러 사이트가 함께 씁니다)
cd buildup365
```

`node_modules/`(설치된 패키지, 루트에 하나), `dist/`(빌드 결과), `.astro/`(캐시)는 명령을 실행하면 자동으로 생기는 폴더입니다. 지워도 되고 저장소에 올리지 않습니다. 폴더를 다른 사람에게 넘길 때는 이 셋을 빼고 넘기면 됩니다.

## 2. 화면으로 보기

```bash
npm run dev
```

브라우저에서 http://localhost:4321 을 엽니다. 파일을 저장하면 바로 반영됩니다. 고친 페이지를 데스크톱 폭과 휴대폰 폭(브라우저 창을 좁히거나 개발자 도구의 기기 모드)에서 모두 봅니다.

## 3. 검증 (필수)

```bash
npm run check     # 타입·문법 오류
npm run verify    # 빌드 + 링크 · 앵커 · 과정 데이터 · 글자 크기 규칙 검사
```

둘 다 "0 errors" / "검증 통과" 가 나와야 합니다. `verify` 가 실패하면 목록에 파일과 이유가 나옵니다.

| 메시지 | 뜻 · 조치 |
|---|---|
| `허용 목록에 없는 외부 링크` | 새 외부 주소를 넣었을 때. 주소가 맞으면 `scripts/verify.mjs` 의 `ALLOWED_HOSTS` 에 도메인 추가 |
| `금지된 외부 링크` | 옛 oopy 주소. 내부 페이지나 갤러리로 바꿉니다 |
| `페이지 없음` / `앵커 없음` | 링크 대상 주소 오타. `/teaching/` 처럼 끝에 `/` 가 붙는지 확인 |
| `courseDetails.ts ...: 'kind' 누락` | 새 기수 항목에 필수 값이 빠짐. [EDITING.md](./EDITING.md) 의 표 참고 |
| `세부 페이지가 빌드되지 않음` | `slug` 오타 또는 항목 문법 오류(쉼표·따옴표) |
| `font-size 15px — 토큰만` | px 를 직접 씀. `var(--t-body)` 같은 토큰으로 교체 |

## 4. 눈으로 확인할 것

- 고친 페이지 상단부터 하단까지 스크롤하며 깨진 곳이 없는지
- 새 기수를 넣었다면: 교육과정 페이지의 **지금 모집중 카드 · 연간 타임라인 막대 · 프로그램 블록 행 · 세부 페이지** 네 곳에 모두 보이는지
- 상태를 바꿨다면: 배지 글자와 타임라인 막대 색이 바뀌었는지
- 링크를 넣었다면: 실제로 눌러서 열리는지
- 휴대폰 폭에서 가로 스크롤이 생기지 않는지

## 5. 배포 (Netlify)

저장소를 Netlify 에 연결해 두면 `main` 브랜치에 푸시할 때마다 자동 배포됩니다. 설정은 `buildup365/netlify.toml` 에 있습니다.

- Netlify 사이트 설정에서 **Base directory 를 `buildup365`** 로 잡습니다. 그러면 이 폴더 안의 `netlify.toml` 이 읽히고, `buildup365/` 바깥만 바뀐 커밋은 배포되지 않습니다.
- Build command 와 Publish directory 는 비워 둡니다. `netlify.toml` 값(`npm run build && node scripts/verify.mjs`, `dist`)이 쓰입니다. UI 에 값이 들어 있으면 파일보다 우선하니 비우거나 같은 값으로 맞춥니다.
- 검증이 실패하면 배포도 실패합니다. 푸시 전에 로컬에서 `npm run verify` 를 통과시킵니다.
- 배포 로그에서 `검증 통과: 페이지 19개 ...` 줄이 보이면 정상입니다.

연간 타임라인의 "오늘" 세로선은 **빌드한 날짜** 기준입니다. 오래 배포하지 않으면 선이 그 자리에 머무니, 한 달에 한 번 정도는 다시 배포합니다(Netlify 의 "Trigger deploy" 버튼).

## 6. 자주 나는 실수

- 따옴표나 쉼표를 지워서 파일 전체가 오류 → `npm run check` 가 줄 번호를 알려 줍니다.
- 같은 `slug` 를 두 번 씀 → 세부 페이지 하나가 덮어써집니다. `verify` 에서 잡힙니다.
- 사진 파일 이름과 `album.ts` 의 `src` 가 다름 → 빈 칸으로 보입니다.
- `content.ts` 를 직접 고침 → 이 파일은 모아서 내보내기만 하므로 실제 값은 각 데이터 파일에 있습니다.
